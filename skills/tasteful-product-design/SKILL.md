# 有品位的产品设计

让审美选择有依据，让效果图中的产品有可解释的结构。每款产品独立完成：**2 款竞品 → 设计语言 → 艺术方向 → 效果图 → 结构核查与修正 → 简明结构图**。

“有品位”体现为定位、比例、秩序、材质或视觉语言相互协调；它可以克制，也可以鲜明。根据使用场景选择表达，不套用固定配色、艺术流派或布局。

## 开始前：建立产品基准

先使用用户已有的描述、图片、文件和上下文，明确产品类别、目标人群、主要任务、使用环境及本次交付。只有缺失信息会改变方案时才简短追问；普通审美选择由你给出有理由的初稿。

- 区分实体产品的部件结构与数字产品的页面、信息和交互结构。不能从“产品设计”一词直接假定类别。
- 记录必须保留的功能、部件或页面、约束及已知尺寸；区分用户给定事实、设计假设和待确认项。
- 给关键部件或区域设置稳定编号，如 P01、P02。形成一份简短的“结构基准”，后续效果图、核查表和结构图沿用它。
- 多款产品分别建立基准与竞品对，不以一组竞品笼统覆盖全部产品。用户若明确要求共用竞品，说明各自适用性。

用户请求完整设计时走完下列流程，不把每一步变成审批节点。用户只要求某一阶段时，交付该阶段及必要的前置信息，不擅自扩展任务。

## 1. 为每款产品对比 2 款真实竞品

使用当前可用的搜索或浏览工具查找实际产品，优先品牌官网、官方产品页、说明书或官方设计资料。用户已指定竞品时先验证并采用。

选择服务相近需求、能解释设计取舍的两款产品。可以选一款直接竞品和一款同类差异化竞品，但说明选择理由。艺术参考不计入这两款竞品。

按 [竞品对比规范](references/competitor-comparison.md) 形成比较表。记录完整品牌与型号或产品名称、来源链接和实际访问日期。把官方事实、图像观察和推断分开；找不到可靠信息的字段写“未查到”。

从对比中提炼本方案应借鉴的原则、需要避开的缺点和差异化机会。结论必须落到比例、体块、材料、色彩、层级或操作方式等具体设计决策。

如果不足两款可验证竞品，报告当前完成数和证据缺口。零款时只能提供竞品筛选条件或待核实候选，不能把它们算作真实对比。可以继续制作明确标注的暂定概念，不能声称已完成两款竞品对比。

## 2. 拆解设计语言，匹配艺术方向

先分析竞品的构成逻辑，再选择艺术方向，避免先贴“包豪斯”“未来主义”等标签再硬套产品。

用简短的映射解释：**竞品观察 → 产品需要 → 艺术参考中的可用原则 → 本方案具体做法**。参考可以来自艺术、建筑、工艺或平面设计；使用具体作品或人物作为事实依据时核实来源。

给出一个有说服力的主方向及选择理由。用户要求探索，或定位存在实质分歧时，再提供差异明确的备选方向。描述至少涵盖与该产品相关的形态或布局、比例、色彩、材料与表面处理或字体与视觉层级。

说明艺术表达如何支持使用体验，哪些元素不采用。借鉴设计原则，发展自己的造型或界面，不照搬竞品的标志、独特识别构件和整套组合。

缺少可观察的竞品资料时，可以根据用户定位或明确标注的假设提出暂定艺术方向；注明尚未经过竞品证据校准，不伪装成分析结论。

## 3. 制作能被核查的效果图

先确定结构，再用艺术方向控制外观表达。制作效果图前，把产品用途、部件或区域编号、关键比例、相互关系和不可改变项写入制作说明。

- 使用当前环境可用的图像生成、图像编辑、设计或渲染工具，输出实际可查看的图片；有参考图时以其约束形态和结构。
- 先制作一张清楚展示整体方案的主视图，再根据被遮挡的结构补充必要视角。精简视角数量，但不要用氛围场景掩盖连接关系、功能区域或操作部位。
- 同一方案的不同视角保持部件数量、比例、连接方式和材料一致。局部修改优先基于现有图编辑，避免每次重新生成导致方案漂移。
- 实体产品清楚展示外形、材质、接缝及必要的操作部位；数字产品使用有意义的示例内容，保持文本、控件、区域和核心路径可辨认。
- 尺寸未知时表达比例，不标造精确尺寸。图中的细小文字或编号不清楚时，使用可控的排版工具添加，避免把生成乱码当作标签。

若环境没有图像能力，提供可执行的制作说明或提示词，并明确“效果图尚未生成”；不能把提示词称为效果图，也不能编造图片链接。说明继续完成所需的工具能力。

## 4. 对效果图逐项核查结构并修正

制作后重新查看实际图像，按 [结构核查规范](references/structure-review.md) 对照产品基准。先观察证据，再判断，不能仅依据原始提示词推定结果正确。

没有实际图片或没有查看图片的能力时，只能列出待检查项目，明确结构核查尚未完成。

记录“编号／核查项／观察到的证据／结果／修正动作”。结果区分：符合、存在问题、待验证、不适用。被遮挡的部件与未显示的内部结构不能自动判为符合。

发现关键部件遗漏、不同视角冲突、连接不成立或操作受阻时，修正效果图，再复查受影响项目。非关键风格偏好与结构问题分开处理。

常规修正最多进行两轮；仍存在关键矛盾、缺少关键参数或需要专业验证时，交付当前状态和具体缺口，不无限消耗工具，也不标为结构已确认。用户可以指定不同的迭代预算。

实体产品的概念一致性检查不等于工程或可制造性验证；数字产品的静态检查不等于实际交互测试。结论只覆盖已有证据支持的范围。

## 5. 输出对应最终方案的简单结构图

完成核查和必要修正后，基于同一份结构基准画图，使用与最终效果图一致的名称、编号、数量和连接关系。

- 实体产品：输出简洁的外形线稿或部件关系图；只有位置、拆分和连接关系有依据时，才画简化爆炸图。优先标注外壳、主要功能部件、连接件、开合或运动方向。未验证的内部关系用虚线及“概念／待验证”标记。
- 数字产品：输出区域线框图或页面流程图，展示关键区域、入口、动作、目的地和必要状态，保持与效果图一致。
- 选择当前工具能准确表达的 SVG、绘图文件或 Mermaid 等形式；关系图不能冒充几何剖面或工程图。图例解释线型和箭头含义。
- 检查结构图与效果图的一致性；如果画图时发现矛盾，回到相应效果图或基准修正，并更新核查结论。

有关键未决项时，仍可交付明确标注的“暂定结构图”，但不可称为已验证定稿。图应便于快速理解，不堆砌与当前方案无关的零件和说明。

效果图因工具或资料缺失尚未生成时，可交付作为部分成果的“概念关系草图”，注明未与效果图核对；它不能替代标准流程中核查后输出的最终结构图。

## 最终交付

每款产品提供一组对应成果，可整理在同一份报告中：

1. **竞品对比：**恰好两款竞品、选取理由、对比表、来源与日期、设计启示。
2. **艺术方向：**匹配逻辑及可执行的形态、色彩、材质或视觉语言说明。
3. **效果图：**最终图片及必要视角；保留方案名称或版本，能与检查记录对应。
4. **结构核查：**实际检查结果、已修正问题及待验证项。
5. **简明结构图：**与最终效果图对应，标注编号、关键关系和概念边界。

直接展示可查看的图片与图示，并附文件或结果链接。缺失项就写明缺失及原因。跟随用户语言，不把“更高级”“更有质感”等空泛评价当作设计依据。
